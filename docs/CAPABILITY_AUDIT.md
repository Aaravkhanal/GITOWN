# GITOWN capability audit

Updated: 2026-10-05

This audit checks the nine capability groups requested against the shipped product code and the current working tree. "Implemented" means a usable bounded implementation exists; it does not mean full GitHub parity or production readiness. See [Product phases](PRODUCT_PHASES.md) and [Roadmap](ROADMAP.md) for the wider boundaries.

| Capability                                                     | Status                               | Evidence and remaining boundary                                                                                                                                                                                                                                                                                                                                                        |
| -------------------------------------------------------------- | ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Formal pull request reviews and approvals                      | Implemented                          | Commit-bound approve/request-changes reviews, stale-review handling, dismissal audit, required approval counts, named reviewers and crew rules are in `internal/app/protection.go` and the Unite UI. Reviews on heads that exist only on a remix remain a limitation.                                                                                                                  |
| Inline diff comments and resolved conversations                | Implemented                          | Commit/file/side/line-anchored threads, replies, outdated marking and resolution are backed by `internal/app/collaboration_depth.go`; merge protection can require resolution.                                                                                                                                                                                                         |
| In-app notification inbox                                      | Implemented                          | Paginated, filterable inbox, unread count/badge, subscriptions and event notifications are in `internal/app/notifications.go` and the workspace UI. Email delivery still depends on SMTP configuration.                                                                                                                                                                                |
| Issue assignees and milestones                                 | Implemented                          | Multi-assignee issue flows, member validation, assignment notices, due-dated milestones, progress and filters are implemented in `internal/app/issue_tracking.go` and `internal/app/milestones.go`.                                                                                                                                                                                    |

## Implementation plan

1. Browser code experience is shipped: upload and rename with stale-head protection, blame access, branch compare, Markdown rendering and syntax coloring. Remaining code-browser work includes the complete tags UI and import/export UX.
2. Close the account-security gate: enable verified-email enforcement after SMTP is configured; add general step-up checks for sensitive actions, recovery-code regeneration, comprehensive security notices and durable abuse decisions. Email verification, recovery and TOTP are implemented using the existing durable email outbox and audit patterns.
3. Add observability and operations foundations: structured request/job metrics, traces, health/readiness probes, dashboards and alerts; worker retry/dead-letter visibility; runbooks; scheduled cleanup and orphan reconciliation; automated backup restore proof.
4. Harden for public beta: isolate Git and workflow processes, enforce quotas at the OS/process boundary, add abuse controls and rate limits, prove webhook/event durability, run load/soak and failure tests, and obtain an independent security review before accepting untrusted public workloads.
5. Keep the roadmap honest: Routes remains planning-only until sandbox review signs off on immutable checkout, ephemeral credentials, redaction, process/network isolation, live resource caps and process-tree cancellation. Treat embedded sshd, advanced Git hosting, high availability and enterprise identity as separately scoped follow-up work.

## Current implementation slice

The browser code experience and the account-security flows are shipped. Password recovery, opt-in verified-email enforcement, and TOTP MFA span migrations, APIs, the mail outbox and UI. Password reset invalidates all sessions and personal tokens; MFA challenges block password-only sign-in. General step-up checks and stronger operational controls remain gated work.

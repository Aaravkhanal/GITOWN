The development alpha is **not ready for untrusted public hosting**. Email verification is available with optional enforcement; TOTP MFA, a hardened Git process sandbox, an embedded SSH server, and a durable receive-event queue are not available. Repository and account quotas are checked before a pack is accepted and again after unpack. A push that exceeds the quota has its new refs rolled back, and the client receives HTTP 413 without a success report. Owners can opt into branch rules. Require Unite, required checks, resolved conversations, an up-to-date branch, signed commits, maintainer approval, and restricted push are all off until an owner turns them on. Those rules are enforced for browser edits, API merges, HTTPS pushes, and the SSH gateway. The SSH gateway is a forced command, not an embedded sshd, and it trusts the fingerprint argument. LFS supports batch upload, download, and path locks, without multipart transfer. District secrets require `GITOWN_SECRET_KEY` and are never logged. Immediate email without SMTP is recorded in the outbox and is not delivered to a mailbox. Drop provenance is verified only against SSH signing keys the publisher registered. The invoice ledger does not charge a card.

Current limits: 100 repositories per account, 20 active tokens per account, 30-day token life, 7-day session life, 30-day soft-deletion recovery, 100 returned repositories/issues/PRs, 200 comments per issue or pull request, 30 commits per history view, 4 MiB command output, 512 KiB displayed blobs, 100 MiB incoming Git request/pack, 20-second browse/merge subprocess deadline, 2-minute transport deadline, and four concurrent Git transports per API process.

## Merge consistency

Each merge request carries the head/base SHAs shown in the UI. Changed branches cause a 409. A database advisory lock serializes API merge operations for a repository. Git creates the merge objects before a durable `merging` record stores the intended result and expected base. `git update-ref` advances the base only if it still equals the expected SHA. Database finalization then marks the PR merged and records activity in one transaction.

If the process stops between Git and database finalization, retrying the merge reconciles the persisted intent. If the merge is already an ancestor of the base, the database can finalize safely. If the base still equals the expected old SHA, the saved ref update can resume. An unrelated base movement leaves the intent pending for manual inspection instead of guessing and overwriting history. The UI exposes a recovery action. Full automated reconciliation is a later milestone.

Head-branch changes after the final SHA check do not change the captured commit included in the merge. Merge Guards count only each reviewer's latest non-dismissed decision for the exact head SHA, so a new push invalidates earlier approvals. Optional rules can also require resolved conversations on that head, an up-to-date branch, a successful status for each required check context, signed commits, an owner or maintainer approval, and owner/maintainer-only pushes. Draft Unite requests cannot merge. Squash creates one commit on the base. Rebase replays the branch, then the base ref moves to that commit. Source-branch deletion runs only after the base ref update succeeds and never deletes the base or default branch.

## Storage consistency

Repository creation writes storage before committing metadata. A failure can leave an unreferenced directory, which is inaccessible through repository routes. Do not automatically delete those directories; retain them for reconciliation. Backups in this release require writes to be stopped. Database and Git storage must be restored from the same backup.

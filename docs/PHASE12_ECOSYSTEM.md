# Phase 12 — Ecosystem implementation and decisions

## Implemented in this update

### Wiki attachments

Browser uploads create ordinary Git commits under `.gitown/wiki/attachments/<page>/<file>`, so they travel with clone, history, backup, and export. Uploads are limited to 512 KiB (the Git store per-blob limit) and to PNG/JPEG/GIF/WebP/PDF with a matching extension. The API validates content bytes, rejects HTML/SVG and arbitrary file types, enforces the same branch-head conflict and branch-protection checks as wiki edits, and serves only validated content with `nosniff` and a restrictive CSP. The web UI lists and uploads assets; embedding an attachment inline in Markdown remains follow-up work.

### External security advisories

Supply-chain scans can query the OSV batch API for exact dependency versions in Go, npm, and PyPI manifests, retrieve matching record details, and upsert repository-scoped advisory snapshots and vulnerability alerts. Non-exact npm/PyPI ranges are skipped rather than incorrectly treated as installed versions; lockfile-aware resolution remains follow-up work. OSV records link to their upstream detail pages. The scan bounds manifest queries and the number of detail lookups; local scanning still succeeds when OSV is unavailable.

The integration is **opt-in**: set `GITOWN_OSV_ENABLED=true` to send package names and exact versions to `api.osv.dev`. It is off by default because that metadata can disclose a private repository's dependency inventory. Operators should review the OSV service's current data handling and their organization's privacy policy before enabling it. Scan results report `disabled_private_metadata_opt_in_required`, `no_exact_versions`, `ok`, or `unavailable`.

## Remaining Phase 12 scope and explicit decisions

These are not silently selected by implementation: each needs a product/security decision and its own authorization, API, UI, denial/failure tests, and documentation gate. Sandbox execution additionally remains blocked on the independent security review and proven host-enforced isolation. Billing and enterprise identity are not included in the current implementation scope.

## External API contract

OSV integration uses `POST https://api.osv.dev/v1/querybatch` for package/version queries, then retrieves bounded individual records from `/v1/vulns/{id}`. See the [OSV batch query API](https://google.github.io/osv.dev/post-v1-querybatch/) and [OSV quickstart](https://google.github.io/osv.dev/quickstart/). Upstream records are advisory signals, not a guarantee that a dependency is safe; users should review linked details and verify remediation against their own dependency graph.
